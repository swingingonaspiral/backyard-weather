1. Scope & responsibility

This notice covers Backyard Weather, its separate Google Nest connection tester, and this public information website. The project is maintained by Adam Miculka for personal, non-commercial use. Privacy questions and requests can be sent to the developer.

The application runs on the user’s Windows computer. There is no maintainer-operated cloud database that automatically receives local weather history. This notice describes weather-app version 0.5.1 and the current Nest authorization tester; it does not claim that planned thermostat-event collection is already operating.

2. Google / Nest access

Google access is optional. The user signs in on Google’s authorization pages and chooses the home and devices made available to the project. The application does not receive the user’s Google password. The connection uses the Smart Device Management OAuth scope https://www.googleapis.com/auth/sdm.service. Google’s permission is broader than the read-only calls implemented by the current tester.

A device-list response can contain device and parent-home/room identifiers and names, device type, permissions, current HVAC status, temperature, humidity, mode, and target-temperature or other thermostat traits. The tester processes the returned response in memory and displays thermostat identification, temperature, and HVAC status to confirm the connection. Only the thermostat needed for this project should be selected during authorization.

The purpose is to confirm access and inspect thermostat operation. The intended next feature is a recent heating-cycle overlay to investigate possible furnace influence on outdoor measurements. No thermostat-control commands, camera-media requests, or access to Gmail, Drive, Calendar, contacts, or Google passwords are implemented by this integration.

Current implementation: the tester does not save returned thermostat telemetry, maintain a heating-history archive, consume Pub/Sub events, or send Nest data to OpenAI. Its encrypted authorization file is separate from the weather application.

3. Weather records & notes

The weather app can read configured Ambient Weather or Weather Underground station observations, original NWS forecasts, and historical files the user imports. Records can include timestamps, station/device identifiers, location information supplied by a provider, weather measurements, soil moisture, and data-quality or recovery information.

The application uses these records for charts, comparisons, rainfall verification, experimental local calibration, historical searches, and data recovery. User-created event notes, preferences, local activity/error information, and optional AI conversations are also stored locally. Weather location and device identifiers should be treated as private; they can identify or suggest a home’s location.

5. Storage & retention

Weather history: observations, forecasts, notes, exports, and local backups are kept on the user’s computer until removed or replaced by applicable application controls. They do not have a universal ten-day deletion rule. Copies in OneDrive, exported files, or user-created backups may remain after a local copy is removed.

AI history: the current conversational analyst retains up to 20 conversations and up to 12 saved turns per conversation locally. Legacy snapshot reports and exports may exist separately. Removing local history does not itself remove records retained by an external provider.

Credentials: the original OAuth JSON remains wherever the user saved it. The Nest tester saves a separate Windows-protected authorization bundle, including its refresh token and client secret, until the user removes it. Reauthorization can leave more than one bundle. Access tokens and returned device telemetry are not written to disk by the tester.

Nest telemetry: the current tester processes it temporarily rather than archiving it. Google’s Device Access rules generally prohibit retaining SDM-derived customer data beyond ten trailing days, with narrow exceptions for home, room, and device identifiers and names. A future event collector must implement the applicable retention and deletion controls before being enabled; publishing this notice does not implement those controls. Google data will not be used to train the project’s weather or AI models.

Pub/Sub: when the owner configures event delivery in Google Cloud, messages may be retained in that Cloud project’s subscription under its configured settings. The current setup instructions use seven-day unacknowledged-message retention. The local tester does not consume or purge that queue.

See the Device Access Policies and Device Access terms for Google’s requirements.

6. Security & access

Weather-service keys and saved Nest authorization bundles use Windows user-bound credential protection. This helps protect stored secrets; it does not encrypt the entire weather database, every exported file, or the original Google credentials JSON. Local records, AI conversations and notes are ordinary files unless the computer or storage is separately encrypted.

The application’s interface is served locally, with authenticated local requests; this public information site does not provide remote control of it. External API requests use HTTPS. Users should keep their Windows account, devices, backups, cloud account, and downloaded credential JSON protected and should not place secret files in a public repository.

7. Revoke access & delete data

Disconnect Google: remove the project’s access in Google Account connections or its Nest partner connections. Removing authorization stops future authorized access but is distinct from deleting files already on a computer.

Remove the tester’s saved credentials: close the tester, then delete the nest-auth-*.protected bundles in %LOCALAPPDATA%\BackyardWeather\NestSetup, including any copies in backups. Remove the original downloaded OAuth JSON if it is no longer needed. These steps do not require deleting the main weather database.

Remove other records: use available application controls or, with the app stopped, remove the specific local files you intend to delete. Also address copies in exports, OneDrive, backups, and any Google Cloud queue you manage. Merely deleting the application’s program folder does not delete its separate saved-data folder.

For help locating records, obtaining a copy, correcting a note, or deleting information supplied to the maintainer, use the developer contact link above. The maintainer cannot remotely inspect or erase files on the user’s computer without a separately authorized means of access.

8. This public website

This site contains app information and policy pages only. Its supplied code does not use analytics, advertisements, cookies, embedded trackers, external fonts, contact forms, or a sign-in function. Opening it does not initiate an OpenAI, Nest, or weather-station request.

When hosted on GitHub Pages, GitHub logs visitors’ IP addresses for security. Hosting, network, and email providers may process information under their own policies. Review GitHub’s Privacy Statement and GitHub Pages’ data-collection disclosure.

9. Limited Use & changes

Backyard Weather follows the Google API Services User Data Policy, including its Limited Use requirements, when using or transferring Google user data.

The project does not sell Google user data, use it for advertising or profiling, or train AI models with it. Any material change in Google-data use will require an updated notice and appropriate authorization before that use begins. A later software version may change functionality; this page must be updated to match it rather than treated as blanket permission for new processing.

This project is intended for the owner’s personal use, not as a service directed to children. Questions about this notice: Contact the developer.
